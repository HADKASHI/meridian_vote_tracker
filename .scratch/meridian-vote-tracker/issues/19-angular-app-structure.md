# Shape the Angular app

Type: prototype
Status: resolved
Blocked by: 12

## Question

How is the Angular 22 app structured, and how should its screens look and behave? Cover:
- routing for the screens: import and report, Review inbox, vote page with timeline, positions, snapshots and publication, Jobs list
- the user switcher in the header and how it sets the identity header on every orval call
- the component library (or none)
- field-level validation errors from ProblemDetails
- presenting a 409 for concurrent decisions, stale positions and publications (showing the current state)
- polling a job's progress, the header "N jobs running" indicator
- the snapshot preview dialog ("Remove these votes")

Make a rough clickable prototype of the shell and one or two screens to react to. Needed before slice 1 in [Set the build order](12-build-order.md).

## Answer

Decided by an agent at the user's request (the user delegated this ticket). Evidence, sketches and the prototype verdict: [research/19-angular-app-structure.md](../research/19-angular-app-structure.md). Prototype (static, throwaway): [research/19-angular-prototype/prototype.html](../research/19-angular-prototype/prototype.html), screenshots `01`–`09` beside it, e.g. [Review inbox](../research/19-angular-prototype/01-review-split-pane.png), [409 already decided](../research/19-angular-prototype/03-review-409-already-decided.png), [snapshot preview](../research/19-angular-prototype/07-snapshot-preview-blocked.png). Matches [Design Docker Compose and image builds](18-docker-compose.md): nginx serves `dist/<app>/browser` and proxies `/api/` to the API, so the app uses relative `/api` URLs with no CORS; in dev, `ng serve` proxies `/api` to `localhost:5080` (`proxy.conf.json`).

1. **Routes** (one lazy route file per feature, `withComponentInputBinding`; filters, tabs and pages live in query params so every view is a shareable link):
   - `/imports` (upload + list), `/imports/:importId` (live job, then the report: counts per outcome as filters, warnings, conflicts opened, row records paged on the server)
   - `/review`, `/review/:conflictId` (Review inbox; the child is the decision pane)
   - `/votes` (search by id, title, session, date, "no position"), `/votes/:voteId` (details, position, country votes; `?tab=timeline` pages back by history id)
   - `/positions` (worklist of votes with stance and weight, votes without a position first; Admin edits inline, analysts read)
   - `/snapshots`, `/snapshots/new` (selection form + preview dialog), `/snapshots/:snapshotId` (job, then ranking and per-country breakdown via `?state=FRA`), `/publications` (each reporting quarter's chain: published, superseded, reasons); `/snapshots/compare?a=&b=` only in slice 7
   - `/jobs`; `/` redirects to `/review`; `**` is a not-found page
   - Ids in URLs are the internal ids; the assembly vote id (`MA/2024/003`) is shown, never put in a path.
2. **Folders** (`web/`, path owned by 18): `src/app/core/` (shell, identity, jobs summary, error notices), `api/` (orval output, generated, gitignored), `shared/` (outcome and job-state badges, from → to, score with basis, problem banner, already-decided card, `pollWhile`, `problemToFieldErrors`), `features/{imports,review,votes,positions,snapshots,jobs}/`. A feature imports only `core`, `shared` and `api`, never another feature (ESLint `no-restricted-imports`). Each slice of 12 adds its feature folder. Rejected: NgModules (standalone is the default), layer folders (`components/`, `services/`) that scatter one slice over the tree.
3. **Generated client**: orval `client: 'angular'`, `mode: 'tags-split'`, `retrievalClient: 'both'` (GETs as `httpResource` functions, writes as `inject(HttpClient)` services), generated by `npm run gen:api` before build, test and serve. Input is the committed `contracts/openapi.json` written by `dotnet build`; CI fails when the build changes it. `npm run build` generates first, so the `web` image builds without .NET, and the contract shows in every PR diff. API paths already include `/api`, so orval needs no `baseUrl`.
4. **Component library: Angular Material 22** (M3 theme, CDK). Same release train as Angular, accessible dialog, table, menu, snackbar and form field, Signal Forms support, and test harnesses. Rejected: none (focus traps, menus and tables by hand cost slice time and accessibility), PrimeNG (separate release train and theming), Tailwind alone (styles, no behaviour).
5. **State: signals, no NgRx.** The server is the only source of truth and nothing is cached across features. Reads are orval `httpResource` keyed on route-input signals; writes call the generated service and then `reload()` the affected resource. Two root services hold shared state: `CurrentUser` and `ShellStatus` (item 9). Rejected: NgRx Store or SignalStore (a client cache to keep in step with a server that already serialises everything), TanStack Query (adds a second fetching model beside `httpResource`).
6. **Identity**: the switcher lists users from `GET /api/users` (Dana, Omar, Lena with roles). A functional interceptor sets `X-User-Id: <id>` on every `/api/` request; orval services and `httpResource` both use `HttpClient`, so every call carries it with no mutator. The choice lives in `sessionStorage` (per tab, survives reload), and new tabs start from the last choice in `localStorage`, so two tabs can be Dana and Omar for the CON-05 demo. Switching re-fetches nothing (any user may read everything); actions recompute from the role and stay visible but disabled with a reason ("Admin only"). The server still enforces 401/403; a 401 resets the switcher.
7. **ProblemDetails**: no interceptor rewrites errors. Forms use Signal Forms; `submit(form, { action })` maps `ValidationProblemDetails.errors` to field errors via `problemToFieldErrors` (keys are camelCase JSON paths such as `selection.from`, asserted by an API test; unknown keys go to a form banner). Other problems are switched on a fixed list of `type` values with typed bodies in the OpenAPI document (table in the research note). One interceptor only adds notices: 5xx and network errors become a snackbar showing the `traceId`; 401 opens the switcher. The app sets no correlation header of its own; nginx passes `traceparent` through, and ticket 21 decides whether the browser starts one (an interceptor slot is free for it).
8. **409s show the current state in place of the action, never a toast and never an automatic retry**:
   - **Conflict decision** (`already-decided`): the decision pane's buttons are replaced by the winner's decision (who, when, accept/reject, from → to, comment) and "your decision was not applied and is on the vote's timeline"; the inbox reloads; "Next conflict" moves on (screenshot 03).
   - **Position** (`stale-position`): the row shows "Lena set Yes · weight 4 at 14:02 while you edited" beside the edit, with "Use theirs" or "Save mine over it", which resends with the new revision id as the version.
   - **Publication** (`quarter-published`): the publish dialog shows the quarter's new publication and offers "Replace it", which needs a reason.
9. **Jobs**: `ShellStatus` polls `GET /api/status` (running and queued jobs, jobs finished in the last minute, pending conflict count) every 1 s while any job is active, else every 5 s, paused while the tab is hidden. The header shows "2 jobs running · 1 queued" linking to `/jobs`, plus the Review badge; a job the current user started announces done or failed once in a snackbar with a link. Import and snapshot pages poll their own resource every 1 s with `pollWhile` (chained `setTimeout` after each response, so calls never overlap) until done or failed, keeping the last value while reloading. `/jobs` lists all jobs with place in the queue, progress, and failure reason. Rejected: SSE or SignalR (ticket 10), `setInterval` (overlapping requests on a slow API).
10. **Snapshot preview dialog** (`/snapshots/new`, MatDialog): "Preview…" posts the selection and shows the resolved vote count; a red **blocking** block listing votes without a position, with "Remove these votes" (turns the selection into range-minus-list, shown as "2024-01-01 → 2024-03-31, minus MA/2024/007, MA/2024/041", then previews again) and "Check again" (after the admin sets positions in another tab); and an amber **warnings** block (pending conflicts linking to the inbox filtered to those votes, incomplete votes, the running import with its progress). "Calculate" stays disabled while blocked, then posts, closes, and navigates to `/snapshots/:id`. If the create call returns `no-position` (an import added a vote in between), the dialog reopens on that list. Rejected: an inline preview panel (the ticket wants a deliberate confirm step before a job, and the dialog keeps the warnings next to the button that accepts them).
11. **Review inbox layout: split pane** (prototype variant A): conflict list (vote, subject, current → incoming, import; same-vote rows adjacent) beside a decision pane showing both values with their origins (file, line, uploader), comment and Accept / Keep current. Rejected: variant B (grouped by vote with inline buttons; fast, but hides origins and the comment, inviting click-through). The list item has a `kind` so a later PDF extraction item can join it.
12. **Display conventions**: dates ISO (`yyyy-mm-dd`), as the data uses; scores to 1 decimal with their basis ("62.5 · 10 votes · weight 32"), n/a states unranked and listed last (05); outcome, job-state and glossary words exactly as in GLOSSARY.md.
13. **Frontend tests** (detail for ticket 20): Vitest through the Angular `unit-test` builder (its default in 22), TestBed with Material harnesses, `HttpTestingController` for the identity interceptor, `problemToFieldErrors` and the 409 cards; one Playwright smoke test against compose (upload → report → two-tab decision race). No snapshot tests of markup.
